# Публикация и Telegram · пошаговая инструкция

## 0. Перед началом

- Нужны аккаунт GitHub и новый отдельный учебный бот. Для рекомендуемого режима proxy — ещё аккаунт Cloudflare.
- **Раскрытый в переписке токен сначала отозвать.** В @BotFather используйте `/revoke`, выберите бота и получите новый токен. Старый больше не используйте. Не присылайте новый в чат и не добавляйте в исходники.
- Даже приватное хранение ключа в GitHub Secrets не защищает его, если затем ключ подставлен в публичный JavaScript.
- Учителю нужно согласовать обработку данных детей и передачу в Telegram с правилами школы. Используйте имя или псевдоним без фамилии, телефона и адреса.

## 1. Создать бота и разрешить ему писать

1. Откройте в Telegram **@BotFather**. Проверьте, что это официальный аккаунт.
2. Команда `/newbot` → отображаемое имя → уникальный username, заканчивающийся на `bot`.
3. Сохраните токен в менеджере паролей. Не публикуйте скриншот ответа BotFather.
4. Перейдите по ссылке на **своего бота**, откройте его личный чат и нажмите **Start** или отправьте `/start`.
5. Отправьте ещё одно простое сообщение. Бот не обязан отвечать: у него пока нет обработчика входящих сообщений. Для `sendMessage` он и не требуется.

Если получатель — группа: добавьте бота в группу, разрешите отправку сообщений и отправьте команду `/start@username_вашего_бота`. Права администратора обычно не нужны для обычной отправки в группу; не давайте лишних прав.

> Бот не может первым начать личный диалог с произвольным пользователем. Нужен `/start` именно у этого бота; `/start` в чате BotFather не подходит.

## 2. Надёжно узнать chat_id

### Рекомендуемый способ: локальный скрипт

После `/start` выполните на своём компьютере из папки проекта:

```bash
python3 scripts/get_chat_id.py
```

На Windows: `py scripts/get_chat_id.py`.

Скрипт запросит токен **со скрытым вводом**, вызовет официальный `getUpdates` и выведет только найденные чаты. Токен не сохраняется в файл и не попадает в аргументы shell. Не запускайте его в непонятном чужом онлайн-терминале.

Пример структуры ответа API, без реальных данных:

```json
{
  "message": {
    "chat": { "id": 123456789, "type": "private" }
  }
}
```

Нужен **`message.chat.id`**. Это не `update_id`, не ID самого бота и не `@username`. Для групп/супергрупп ID обычно отрицателен; сохраняйте минус и все цифры. Для личного чата свой ID также можно уточнить у информационного бота, но не передавайте ему bot token.

Если сообщений нет: снова напишите именно своему боту и повторите скрипт. Другой запущенный обработчик мог уже забрать обновления. При `409` `getUpdates` может конфликтовать с webhook или другим приложением. Не удаляйте webhook действующего сервиса автоматически — лучше использовать отдельного бота.

## 3. Создать репозиторий main

1. GitHub → **New repository**. Имя, например `matematika7`.
2. Выберите **Public** для бесплатного GitHub Pages без платного тарифа. Не создавайте в репозитории файл с токенами.
3. В корень загрузите файлы проекта. Обязательная структура:

```text
.github/workflows/deploy.yml
site/index.html
site/config.js
package.json
package-lock.json
scripts/
tests/
```

Не помещайте всё ещё на один уровень внутрь `matematika7/matematika7/`. Не загружайте `node_modules`, `_public`, `.env`, `.dev.vars`, журналы с ключами.

### Через git — надёжнее для скрытой .github

Замените `YOUR-NAME` и имя репозитория на свои; это не секреты.

```bash
git init -b main
git add .
git commit -m "Готовый тренажёр математики 7 класса"
git remote add origin https://github.com/YOUR-NAME/matematika7.git
git push -u origin main
```

Авторизуйтесь стандартным менеджером учётных данных GitHub или GitHub CLI на своём компьютере. Не добавляйте PAT в URL, JS, Actions Variables или этот чат.

Если загружаете через браузер, убедитесь, что папка `.github` действительно попала в репозиторий. При необходимости **Add file → Create new file**, имя `.github/workflows/deploy.yml`, и вставьте содержимое прилагаемого файла. Без него автоматического деплоя не будет.

## 4. Включить GitHub Pages

1. **Settings → Pages**.
2. **Build and deployment → Source → GitHub Actions**. Не выбирайте `Deploy from a branch` и папку `/docs`.
3. Откройте **Actions**. Если Actions отключены для форка, разрешите запуск.
4. Выберите workflow **«Проверить и опубликовать Тетрадь 7»** → **Run workflow**, ветка **main**.
5. Проверьте три зелёных этапа: `check`, `build`, `deploy`.
6. Адрес опубликованного сайта указан в **Settings → Pages**, в результате `deploy` и окружении `github-pages`.

Ожидаемый вид: `https://YOUR-NAME.github.io/matematika7/`. Это шаблон адреса, не уже созданный сайт. Приложение проверено и для такого подкаталога.

Без Telegram Secrets всё публикуется с режимом `off`: ученик решает задачи и скачивает отчёты. Реальные значения не требуются для этой проверки.

## 5А. Прямой режим — как запрошено, но с публичным токеном

**Не рекомендуем для ценного или рабочего школьного бота.** Любой посетитель сможет открыть `config.js`, извлечь токен и управлять ботом. В том числе изменить целевой чат в собственном запросе. Telegram не предоставляет ограничения токена «только sendMessage в chat_id X». Уменьшенные права в группе не устраняют этот риск.

### Repository Secrets

**Settings → Secrets and variables → Actions → Secrets → New repository secret**:

| Name | Value |
|---|---|
| `TELEGRAM_BOT_TOKEN` | **новый** токен от BotFather |
| `TELEGRAM_CHAT_ID` | подтверждённый числовой ID получателя |

Имя Secret вводится точно, без пробелов. Значение — без кавычек. Используются именно Repository Secrets; если создаёте Environment Secrets, нужно отдельно переделать доступ build-job к окружению.

### Repository Variables

В соседней вкладке **Variables → New repository variable**:

| Name | Value |
|---|---|
| `TELEGRAM_MODE` | `direct` |
| `ALLOW_UNSAFE_DIRECT` | `true` |

Сборка намеренно завершится ошибкой, если нет явного `ALLOW_UNSAFE_DIRECT=true`, токен пустой или формат реквизитов неверен. В исходном `site/config.js` оставьте `__TELEGRAM_BOT_TOKEN__` и `__TELEGRAM_CHAT_ID__`.

После изменения Secrets/Variables **повторно запустите workflow**. Само изменение Secret деплой не запускает. Скрипт `scripts/build.py` JSON-экранирует данные и подставляет их только в `_public/config.js` на раннере, не меняя git-источник и не печатая ключ. **Но содержимое артефакта и сайта становится публичным.**

## 5Б. Рекомендуемый режим proxy · токен только у Cloudflare

Схема: **GitHub Pages → Worker → Telegram**. Свой сервер и домен не нужны; используется адрес `workers.dev`. У Cloudflare есть бесплатный тариф с квотами; условия, доступность в регионе и актуальные лимиты нужно проверить в аккаунте. Ориентир Free Workers — 100 000 запросов в сутки, не обещание неограниченного сервиса.

### 1. Подготовить Turnstile

1. Cloudflare Dashboard → **Turnstile → Add widget**.
2. Тип **Managed**. Разрешённый hostname — `YOUR-NAME.github.io` (без `https://` и пути репозитория). Для собственного домена добавьте и его.
3. Получите **site key** и **secret key**. Site key публичен; secret key — только серверный Secret.

### 2. Настроить и развернуть Worker

В `worker/wrangler.toml` замените:

```toml
ALLOWED_ORIGINS = "https://YOUR-NAME.github.io"
REQUIRE_TURNSTILE = "true"
MAX_REQUESTS_PER_MINUTE = "30"
```

Origin не содержит `/matematika7/` и завершающего `/`. Несколько origin — через запятую. `*` не поддерживается намеренно. Origin не является авторизацией; программы вне браузера способны его подделать.

Из корня проекта на своём компьютере, с актуальной LTS Node.js (22 или новее для Wrangler) и входом в свой Cloudflare:

```bash
npx wrangler@4 login
npx wrangler@4 deploy --config worker/wrangler.toml
npx wrangler@4 secret put TELEGRAM_BOT_TOKEN --config worker/wrangler.toml
npx wrangler@4 secret put TELEGRAM_CHAT_ID --config worker/wrangler.toml
npx wrangler@4 secret put TURNSTILE_SECRET_KEY --config worker/wrangler.toml
```

Каждый `secret put` запросит значение интерактивно. Не вписывайте значения прямо в команду и не сохраняйте в TOML. До добавления Secrets Worker отвечает «не настроен» — это безопасное поведение. Запишите HTTPS-адрес Worker, показанный после deploy.

Альтернатива для Secrets: **Workers & Pages → ваш Worker → Settings → Variables and Secrets → Add → Secret**. Исходный код содержит импорт общего форматтера; для публикации кода используйте Wrangler, который собирает его в один Worker, а не вставляйте только `index.js` без зависимого модуля в редактор.

### 3. Указать публичные параметры Pages

В GitHub **Actions → Variables**:

| Name | Value |
|---|---|
| `TELEGRAM_MODE` | `proxy` |
| `TELEGRAM_PROXY_URL` | полный `https://...workers.dev` вашего Worker |
| `TURNSTILE_SITE_KEY` | публичный site key Turnstile |

`ALLOW_UNSAFE_DIRECT` можно удалить или поставить `false`. Telegram Secrets на стороне GitHub в этом режиме не используются; безопаснее удалить ненужные копии, оставив ключ только в Worker. Никакого Cloudflare API-токена в браузере нет.

Повторите Pages workflow. В опубликованном `config.js` должны остаться плейсхолдеры Telegram, но появиться публичные URL/site key. Нажатие «Тест связи» потребует антиспам-проверку.

### Защита и пределы прокси

- Только фиксированный получатель из серверного Secret. Клиентский `chat_id`, токен, URL Bot API и готовый HTML не принимаются.
- Схема и размер JSON до 64 КиБ, длины полей, согласованность количества ответов, CORS, Turnstile с проверкой hostname и action.
- До 30 запросов/мин/IP в памяти одного isolate по умолчанию. **Это best effort, не глобальный надёжный rate limit.** Из-за NAT несколько учеников могут делить IP. Для строгих лимитов и дедупликации нужен общий серверный storage/лимитер.
- Turnstile включён по умолчанию; `REQUIRE_TURNSTILE=false` оставлен только для осознанного локального тестирования, не рекомендован в публичном endpoint.
- Имя, задания и правильность ответов всё равно присланы браузером: прокси не доказывает личность и математическое решение.
- Автоматической дедупликации на сервере нет. При сетевом обрыве сообщение могло дойти — сначала проверьте чат.

## 6. Проверка связи и работы ученика

1. Откройте **опубликованный** сайт, не HTML-файл с диска.
2. **Уголок учителя → Telegram: проверка связи**. Статус должен быть настроен.
3. В proxy пройдите Turnstile. Нажмите «Отправить тестовое сообщение» один раз.
4. Убедитесь, что сообщение действительно появилось в нужном чате. На сайте успех показывается только после `ok:true` и целого `message_id`.
5. Откройте любой урок → ДЗ → подпишите тетрадь псевдонимом → решите → завершите.
6. Посмотрите разбор, при желании скачайте TXT/JSON. Отметьте согласие, пройдите проверку и нажмите «Отправить результат».
7. В Telegram должны быть: ученик, урок, вариант, баллы, оценка, первая попытка/пропуски, активное время, ошибки, ID отчёта и предупреждение о клиентских баллах. Длинные ошибки/обоснования сокращаются; полный вариант — в скачиваемом отчёте.
8. После подтверждения кнопка повторной отправки блокируется **на этом устройстве**. Это не защита от изменения localStorage и не серверная идемпотентность.

## 7. Что делать при ошибке

| Симптом | Проверка |
|---|---|
| Workflow отсутствует | `.github/workflows/deploy.yml` в корне; ветка `main`; Actions включены |
| Красный `check` | открыть упавший тест; не удалять проверки ради зелёного деплоя |
| `build`: direct заблокирован | Variables `TELEGRAM_MODE=direct`, `ALLOW_UNSAFE_DIRECT=true`; осознанно принять раскрытие |
| `build`: реквизиты отсутствуют | точные имена Repository Secrets, без кавычек/пробелов; повторить workflow |
| `deploy`: permission/Pages | Source = GitHub Actions, разрешения из workflow, окружение `github-pages`, публикация public repo |
| Пустой экран с диска | запускать HTTP-сервер или Pages, не `file://` |
| 404 у JS/CSS | не потеряна `site/assets/`; публикуется `_public/`, не корень проекта |
| Сайт пишет «не подключён» | обновить Variables и запустить workflow заново; перезагрузить сайт |
| 401 Telegram | токен неверен/отозван; новый в Secrets, direct — повторный деплой |
| 400 Telegram | неправильный `chat_id`, пропущен `/start`, группа недоступна; сверить через `getUpdates` |
| 403 Telegram | бот заблокирован или лишён права писать |
| 429 | выдержать `retry_after`, не нажимать многократно |
| Worker: origin запрещён | точный HTTPS origin, без пути/слеша, совпадает с реальным доменом сайта |
| Turnstile не появляется | site key в GitHub Variables; hostname в Cloudflare; сеть/расширения браузера |
| Worker требует challenge | проверить обе половины ключей и `REQUIRE_TURNSTILE`; заново пройти проверку |
| Тайм-аут/сеть/CORS | сохранить отчёт; проверить доступность сервисов; **сначала посмотреть чат**: доставка могла состояться |

**Не используйте `mode: 'no-cors'`: opaque-ответ не подтверждает доставку.** В проекте нет автоповторов, GitHub PAT и отправки токенов в логи.

## 8. Изменения и отключение

Обычные изменения — commit/push в `main`: тесты и Pages запускаются автоматически. Изменение Secret/Variable — затем ручной Run workflow. PR проходят тесты **без публикации и без подстановки секретов**.

Чтобы отключить отправку: `TELEGRAM_MODE=off` и повторный деплой. Если direct-токен уже был опубликован, одного выключения мало: **отзовите его у BotFather**, так как старую копию могли сохранить. Старые артефакты/кэши также могут содержать ключ; отзыв — первичное действие.

Для переноса на другой статический хост публикуется содержимое `_public/`; все URL ресурсов относительны. При смене домена proxy обновите Origin и hostname Turnstile. История localStorage между разными origin не переносится.
