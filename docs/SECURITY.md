# Безопасность и данные

## Не использовать ранее раскрытые токены

Любой bot token, попавший в переписку, исходники, опубликованный сайт или скриншот, считайте скомпрометированным. Сначала отозвать в @BotFather, затем выпустить новый. Удаление текста из чата или `config.js` не делает старый токен снова безопасным.

В комплекте нет настоящих ключей и персональных ID получателя. В `site/config.js` только плейсхолдеры. Локальный сканер проверяет вероятные Telegram/GitHub-токены и приватные ключи, но не гарантирует отсутствие любого секрета. Не коммитьте `.env`, `.dev.vars`, артефакты direct-сборки и логи.

## Режимы отправки

### off

Режим по умолчанию. Сайт не обращается к Telegram или Cloudflare. Проверка ответов и локальные отчёты работают без этих сервисов. Учебные данные и шрифты находятся в проекте.

### direct

Запрос `sendMessage` идёт из браузера. Для работы токен должен находиться в опубликованном JS. Хранение исходного значения в GitHub Secrets защищает от случайного коммита, **но не от извлечения ключа посетителем после сборки**. Артефакт GitHub Pages также может содержать этот токен.

Токен даёт контроль над ботом. Нет настройки Telegram «только этот метод и один чат». Клиентский фиксированный `chat_id` можно заменить в своём запросе. Отдельный бот без ценных переписок и лишних групп только уменьшает ущерб; техническим ограничением токена это не является.

Direct требует `TELEGRAM_MODE=direct` и отдельного `ALLOW_UNSAFE_DIRECT=true`. Для рабочего бота рекомендуем proxy.

### proxy

В браузере только публичные HTTPS URL и site key Turnstile. Telegram token, целевой chat_id и Turnstile secret key находятся в серверных Secrets Worker. Worker не принимает произвольный URL, чат или готовый HTML; сам формирует сообщение с экранированием.

Предусмотрены:

- точный allowlist Origin, без wildcard;
- только POST JSON, безопасный preflight OPTIONS;
- ограничение тела 64 КиБ и длины/типы полей;
- повторный подсчёт согласованного количества ответов и учебной оценки;
- Turnstile включён по умолчанию; проверяются hostname и action;
- best-effort лимит в памяти одного isolate (30 запросов/мин/IP по умолчанию);
- тайм-ауты, отсутствие автоматических повторов, отсутствие секретов в ответах ошибок;
- наружу возвращаются только результат доставки и номер сообщения.

**Пределы:** CORS/Origin не являются аутентификацией; программный клиент может подделать Origin. Лимит в памяти не глобальный и сбрасывается при перезапуске/смене isolate. Turnstile снижает спам, но не доказывает, что задание решено нужным ребёнком. Для строгой защиты нужны авторизация, серверная выдача/проверка задания, постоянный лимитер и журнал идемпотентности; это не реализовано и не обещано.

## Проверка математики

Браузерный checker не использует `eval`, `Function`, исполнение присланного кода или случайные подстановки значений. Выражения разбираются ограниченной грамматикой; числа — точные BigInt-дроби; равенство рациональных выражений — через многочлены. Есть ограничения длины, степени, числа токенов/членов и глубины.

Это не полноценная CAS: нет функций, тригонометрии, корней и произвольной логической семантики. Проверка ОДЗ консервативна: новые знаменатели допускаются только с явно указанными линейными исключениями. У допустимого, но неподдержанного формата может потребоваться другая запись.

Независимый Python/SymPy-скрипт — **только инструмент разработчика для доверенного авторского банка**, не серверная проверка пользовательского ввода.

## Доставка и дубликаты

Telegram `sendMessage` не принимает ключ идемпотентности этого приложения. Если сеть оборвалась после приёма сообщения, сайт не может уверенно отличить «не пришло» от «дошло, но ответ потерян». Ошибка с неопределённой доставкой показывается явно. Автоповторов нет. Прежде чем повторить вручную, проверьте чат.

Кнопка после подтверждённой доставки блокируется локально. Очистка/изменение localStorage, другой браузер или собственный HTTP-запрос способны обойти эту блокировку. Серверной дедупликации нет.

## Какие данные и где хранятся

### Устройство ученика

В localStorage origin сайта, ключ `tetrad7:state:v1`:

- имя/псевдоним и необязательное обозначение класса;
- настройки фильтров/оценивания;
- до 200 последних начатых и завершённых работ;
- ответы, черновики, обоснования, подсказки, активное время, результат отправки.

Данные не синхронизируются между устройствами. При запрете localStorage используется память до закрытия вкладки. Есть скачивание отчётов, очистка истории и удаление всех локальных данных. Очистка браузера не удаляет уже доставленные сообщения Telegram.

### После отдельного согласия

В Telegram передаются имя/псевдоним, класс при заполнении, тема, вариант, баллы, оценка и пороги, активное время, ошибки и сокращённые обоснования. Полный TXT/JSON можно скачать без отправки. Тест связи не содержит данных ученика.

В proxy полный JSON отчёта проходит через инфраструктуру Worker, даже если текст Telegram будет сокращён. Проект не записывает его в серверную БД и сам не ведёт логи содержимого. Cloudflare и Telegram могут обрабатывать технические данные по своим правилам. Turnstile загружает внешний скрипт и обрабатывает, в частности, технические сведения об устройстве/соединении и IP. Ограничитель в памяти использует IP кратковременно; это не база учеников.

### Организационные обязанности

Учителю/школе нужно определить правовое основание обработки данных детей, порядок получения необходимых согласий, круг доступа к чату, срок хранения сообщений и политику удаления. Этот шаблон не заменяет юридическую оценку и школьную политику. Не вводите телефон, адрес, фамилию и лишние персональные сведения. Не отправляйте чувствительные медицинские или иные специальные данные в комментариях.

## Оценки не заверены

Имя, банк заданий, баллы и localStorage доступны ученику. Это учебный тренажёр и канал обратной связи, не защищённая контрольная или экзамен. Прокси проверяет структуру отчёта, **не математическую истинность и личность**. В сообщении это указано. Произвольное доказательство/чертёж проверяет человек.

## Если утечка всё же произошла

1. Немедленно `/revoke` в BotFather.
2. Отключить отправку (`TELEGRAM_MODE=off`, повторить Pages workflow).
3. Проверить группы/чаты бота и историю сообщений, уведомить ответственных по правилам школы.
4. Удалить ненужные ключи/артефакты; при необходимости очистить git-историю. Это вторично относительно отзыва ключа.
5. Новый ключ разместить только в нужном secret-хранилище. Для работы выбрать proxy и выполнить ручной тест доставки.
