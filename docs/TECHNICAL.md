# Код и устройство проекта

## 1. Технологический выбор

Vanilla HTML/CSS/ES-модули: нет runtime-зависимостей, серверного рендеринга и тяжёлого бандлера. GitHub Pages раздаёт только статику. Python-скрипт копирует её и подставляет настройки; npm нужен для проверок, а не для работы ученика. Playwright — только dev-зависимость. Шрифты локальные, рисунки — встроенные SVG.

Маршрутизация через hash, поэтому не нужен серверный fallback/SPA rewrite:

| Маршрут | Назначение |
|---|---|
| `#/catalog` | модули, уроки, фильтры |
| `#/challenge` | отдельный вход в 24 комплексные темы |
| `#/lesson/a11` | памятка и выбор работы |
| `#/train/a11?work=homework&variant=17` | фиксированное ДЗ |
| `#/result/<id>` | итог и отправка |
| `#/stats`, `#/homework` | история/прогресс и локальные ДЗ |
| `#/theory`, `#/program` | все памятки, методическая карта |
| `#/settings`, `#/privacy` | инструкции учителю и данные |

Параметр `variant` — 1–30 букв/цифр/`_`/`-`. Имя и ответы в URL не передаются.

```html
<html lang="ru">
  <!-- локальные CSS, title/description/viewport -->
  <body>
    <aside id="sidebar" class="sidebar"></aside>
    <div class="workspace">
      <header id="topbar" class="topbar"></header>

    </div>

      <div id="modal-content"></div>
    </dialog>
```

Используются labels, fieldset/legend, focus-visible, aria-current, aria-live для ответа, progressbar, нативный dialog. Предусмотрено reduced-motion. Основной текст задачи крупнее вспомогательных подписей. Меню на телефоне выезжает с перекрытием, горизонтальный скролл страницы не нужен; лента номеров заданий может прокручиваться внутри.

## 4. Контракт задания

```js
{
  id: 'a38-01',
  lessonId: 'a38',
  type: 'expression',
  prompt: 'Раскрой квадрат суммы: <span class="math">(x + 2)²</span>.',
  answer: 'x^2+4x+4',
  alternatives: [],
  validation: { form: 'expanded' },
  hint: 'В квадрате суммы есть удвоенное произведение слагаемых.',
  explanation: 'Используй a² + 2ab + b².'
}
```

`prompt` — доверенный авторский HTML, не ученический ввод. Поля, введённые учеником, экранируются перед HTML. У варианта выбора хранятся стабильные `value` и перемешанные `label`; последовательности содержат `steps` и правильные номера через `;`. Для независимых переставляемых шагов указаны альтернативные порядки.

Банк конечный и параметрический: `index=0…47`, 3 формы × 16 параметров. `getWork` перемешивает один и тот же пул seed-ом `lessonId + variant`, затем берёт 8 первых для КР и следующие 8 для ДЗ. Для **одного варианта** пересечений нет. Между разными вариантами повторения возможны; практика тоже может повторять ранее встречавшиеся задачи.

Комплексные задания дополнительно имеют `challenge: true`, `skills`, `solutionSteps` и `audit`. Последнее поле содержит доверенную авторскую математическую модель для независимого dev/CI-аудита, не выполняется в браузере. Решение показывается после попытки и в итоговом разборе; в TXT/JSON входят `solutionSteps`. Наборы из нескольких чисел используют `type: 'list'` и `validation: { ordered: true }`. Балл — один за полный ответ; порядок множества корней при этом не важен.

Старые ID A01–A58, G01–G35, S01–S11, их номера и seed не изменены. Добавление банка не сбрасывает существующую историю.

## 5. Нормализация и альтернативы

Проверщик: `site/assets/js/checker.js`. Существенная часть нормализации (полная функция — в файле):

```js
const normalized = raw
  .replace(/[⁰¹²³⁴⁵⁶⁷⁸⁹]+/g, part =>
    '^' + [...part].map(c => '⁰¹²³⁴⁵⁶⁷⁸⁹'.indexOf(c)).join(''))
  .replace(/½/g, '(1/2)')
  .normalize('NFKC')
  .replace(/[−–—﹣]/g, '-')
  .replace(/[×·⋅∙]/g, '*')
  .replace(/[÷:]/g, '/')
  .replace(/(\d),(?=\d)/g, '$1.')
  .toLowerCase();
```

До нормализации числовой парсер отдельно распознаёт смешанное число, например `−2 1/3` или `1½`. Кириллические похожие буквы в математических выражениях сопоставляются с латинскими. Это не функция для произвольного русского текста.

Альтернативы сравниваются не простым совпадением отформатированной строки:

```js
const alternatives = [task.answer, ...(task.alternatives || [])];
for (const answer of alternatives) {
  const result = compareExpressions(input, answer, task.validation || {});
  if (result.correct) return { ...result, format: true };
}
```

Внутри `compareExpressions` обе стороны разбираются в рациональные функции `N/D`. Точное равенство проверяется сравнением многочленов `N₁D₂` и `N₂D₁`, без случайных числовых подстановок. Новые запреты на область определения не разрешаются автоматически. После равенства проверяется форма: раскрытые скобки/приведённые подобные или произведение множителей; для выбранных задач — до линейных множителей.

| Тип | Примеры допустимого ввода | Важное |
|---|---|---|
| number | `−3`, `0,75`, `3/4`, `2 1/3`, `1/2+1/4` | число; по умолчанию небольшой относительный допуск 1e−9 |
| fraction | `3/4`, `6/8`, `0,75` | точное равенство; для 1/3 не писать 0,33 |
| expression | `x²+2x+1`, `1+2*x+x^2` | `^`, неявное умножение, скобки; без `=` перед формулой |
| coordinates | `(2; −3)`, `x=1,5; y=2` | x затем y; лучше `;`, чтобы не путать с десятичной запятой |
| list | `−2; 3`, `{3; −2}` | порядок обычно не важен, кроме явно ordered; повторения учитываются |
| choice | выбор готового варианта | значение должно присутствовать в options |
| sequence | `2; 1; 3` | порядок важен; можно нажимать кнопки номеров |
| text | `биссектриса`, предусмотренные словесные альтернативы | короткий ответ, не интеллектуальная оценка любого доказательства |

Знаменатель с несколькими множителями пишите в скобках: `1/(2x)`, а не двусмысленное `1/2x`. Научную запись `1e3` замените на `1000`. Названия функций, корни и тригонометрия не поддерживаются.

Ограничения парсера: 320 символов, 180 токенов, 48 уровней вложенности, 256 членов, суммарная степень до 80; показатель — целое от −12 до 60. ОДЗ проверяется консервативно по явно указанным линейным исключениям, в том числе по нескольким переменным. Это не универсальная CAS.

## 6. Попытки, время и отчёт

`checkSessionAnswer` сначала вызывает checker. Если `format:false`, первая попытка не фиксируется. Иначе `firstCorrect` и `firstInput` записываются один раз; последующие `latestCorrect`/`lastInput` нужны для обучения и разбора.

```js
firstCorrect: typeof previous.firstCorrect === 'boolean'
  ? previous.firstCorrect
  : result.correct
```

Процент баллов = верные первые ответы / все задания × 100. Прогресс = математически оформленные первые ответы / все задания × 100. Поэтому прогресс может быть 100%, а баллов — меньше. Пропуски дают 0 баллов. Подсказки отмечаются в отчёте, отдельного штрафа за них нет.

Время увеличивается только пока вкладка видима; это активное время открытой работы, а не доказательство фактической занятости ребёнка. При переключении страницы/перезагрузке сохраняется черновик. Завершённая работа не редактируется; новый вариант создаёт новую сессию.

Пороги копируются в сессию при старте, поэтому последующее изменение настроек не переоценивает старую работу. Отчёт содержит исходный текст шагов для последовательностей, первые ответы, исправления и обоснования. В Telegram всё ограничивается длиной; в TXT/JSON обоснование сохраняется до 1200 символов на задачу.

## 7. buildTelegramMessage / sendToTelegram

Полные реализации: `report-message.js` и `telegram.js`. Общий форматтер отделён, чтобы Worker не тянул весь банк задач.

```js
export const escapeHtml = value => String(value ?? '')
  .replace(/&/g, '&amp;').replace(/</g, '&lt;').replace(/>/g, '&gt;')
  .replace(/"/g, '&quot;').replace(/'/g, '&#39;');

// В buildTelegramMessage: значения обрезаются ДО экранирования,
// а лимит готового сообщения контролируется после экранирования.
// Разрешённые <b>/<i>/<code> создаёт программа, не ученик.
```

Поток direct:

```js
const body = new URLSearchParams({
  chat_id: String(config.chatId),
  text: buildTelegramMessage(report),
  parse_mode: 'HTML',
  disable_web_page_preview: 'true'
});
const response = await fetch(
  `https://api.telegram.org/bot${config.botToken}/sendMessage`,
  { method: 'POST', body, signal, credentials: 'omit' }
);
const data = await response.json();
// Только response.ok && data.ok === true && integer message_id → успех.
```

Используется AbortController, пользовательские сообщения для 400/401/403/429, обработка не-JSON, сетевого обрыва и неопределённой доставки. URL/исходное исключение с токеном не выводится. `no-cors` намеренно не применяется. Автоповторов нет.

Поток proxy:

```js
fetch(config.proxyUrl, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ report, turnstileToken }),
  credentials: 'omit'
});
```

Worker валидирует JSON, проверяет антиспам, заново формирует сообщение и использует только свой `env.TELEGRAM_CHAT_ID`. Ни токен, ни произвольный chat_id не принимаются от браузера. В ответ — `{ ok: true, messageId }`, без лишних данных Telegram. Это защита ключа, не заверение оценок.

## 8. deploy.yml и подстановка

Готовый полный файл: [`.github/workflows/deploy.yml`](../.github/workflows/deploy.yml). Три job: `check → build → deploy`.

Ключевой участок:

```yaml
- name: Подставить настройки в публикуемую копию
  env:
    TELEGRAM_MODE: ${{ vars.TELEGRAM_MODE || 'off' }}
    ALLOW_UNSAFE_DIRECT: ${{ vars.ALLOW_UNSAFE_DIRECT || 'false' }}
    TELEGRAM_BOT_TOKEN: ${{ secrets.TELEGRAM_BOT_TOKEN }}
    TELEGRAM_CHAT_ID: ${{ secrets.TELEGRAM_CHAT_ID }}
    TELEGRAM_PROXY_URL: ${{ vars.TELEGRAM_PROXY_URL }}
    TURNSTILE_SITE_KEY: ${{ vars.TURNSTILE_SITE_KEY }}
  run: python scripts/build.py --output _public
- uses: actions/upload-pages-artifact@v4
  with:
    path: _public
```

У `deploy` есть `pages: write`, `id-token: write`, environment `github-pages` и `actions/deploy-pages@v4`. Секреты не подставляются в PR; публикация только для push/main или ручного workflow. В раннере используется JSON-экранирование целого строкового литерала, а не `sed` с shell-интерполяцией токена. Исходный `site/config.js` не изменяется.

**Secrets → публичный JS остаются публичными.** Скрипт предотвращает синтаксические ошибки/случайный режим direct, но не делает невозможного «секрета в браузере».

## 9. Добавить тему или тип задачи

1. Добавьте запись в `curriculum.js` с честным уровнем, памяткой, примером, типичной ошибкой и тегами.
2. Реализуйте генератор нужного subject в `bank-*.js`. Все 48 индексов должны создавать корректное и отличающееся полное задание.
3. Для нового типа расширьте checker, input/render/help и report; сначала напишите независимые правильные/неправильные примеры.
4. Добавьте SVG в `diagrams.js`, если нужен. Не давайте схеме неправильную ориентацию угла под предлогом «не в масштабе».
5. Выполните тесты и `node scripts/export-curriculum.mjs`.
6. Изменение уже опубликованных ID/смысла задания может сделать старый локальный отчёт несогласованным: отчёт восстанавливает условие по ID. Сохраняйте старые ID неизменными; при несовместимой перестройке нужна миграция версии банка/хранилища или явное уведомление об очистке истории. Автоматическая миграция произвольных изменений не реализована.

Количество задач одной работы задано в `bank.js`; изменение требует согласовать UI, storage, Worker-ограничения и тесты. Свойство размеров в config намеренно не выставлено как неработающая пользовательская настройка.
